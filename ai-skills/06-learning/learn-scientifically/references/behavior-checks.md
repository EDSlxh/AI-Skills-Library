# 教学行为验收用例

用于修改流程后的人工对话检查。格式校验不能证明教学行为正确，这些用例也不测量长期学习效果。没有实际运行时应报告“已编写用例”，不能报告“行为测试通过”。

在隔离的测试会话和临时目录中使用当前技能。每例先给请求及原始材料，记录实际回复和文件变化，再依据下面的可观察结果判定。只有本例明确要求保存时才保存测试记录；不把示例回答混入真实学习档案，不要求使用外部服务或多代理。

## 1. 零基础开始

请求：“我完全没有学过导数，今天只有 15 分钟，请直接开始带我学。”

观察：

- 从有限、可观察的目标开始，提供足够的直观输入或示例。
- 本单元有与目标匹配的过关任务和判断标准。
- 不连续追问学习者尚未接触的形式定义；首次练习可跟随必要示范。
- 无作答前只记录已接触或待验证，不生成通过结果。

## 2. 用户直接要完整解释

请求：“别测我，也别让我先回答。直接完整解释梯度下降，给一个算得清楚的例子。”

观察：

- 直接交付完整解释和核对过的例子，不把测验或再次确认设为前置条件。
- 用户没有提交的作答保持未验证，不因完整讲解生成了就升级状态。
- 不因此强制保存资料、安排提醒或安装工具。

## 3. 题目已给出，用户尚未作答

请求：“请只给一道矩阵乘法练习，先不要答案。我晚一点回答，也暂时不保存文件。”

观察：

- 给出可解的题目及必要条件，等待回答，不同时泄露参考解。
- 不代写学习者答案，不给分，也不把尚未提交当作错误。
- 对话内保留待回答题目，不写学习文件；若之后用户明确要求保存，则断点仍为待回答。

## 4. 参考答案有误

材料：“题目是 2x + 3 = 7，参考答案写 x = 3。我答 x = 2。”

请求：“检查我的答案并说明下一步。”

观察：

- 用代入或等价变形核查，得到 x = 2，指出参考答案有误。
- 不为了符合参考答案给学习者贴上误解标签。
- 若已有采用错误参考解的评分，保留更正理由与历史，受影响结果先待复核再更正。

## 5. 复习积压与日期一致性

测试日期为 2026-10-15，时区 Asia/Hong_Kong。用户已要求在测试目录保存记录，队列有以下项目；准备材料中保留每条自己的最近作答引用。

| 条目 | 到期日 | 已有依据 |
| --- | --- | --- |
| Q01 | 2026-10-10 | 当前目标的必要前提，最近一次需步骤提示 |
| Q02 | 2026-10-11 | 最近出现概念误解 |
| Q03 | 2026-10-12 | 正确过一次，仍待隔时检验 |
| Q04 | 2026-10-13 | 较低优先级的扩展知识 |
| Q05 | 2026-10-14 | 当前任务关联较弱 |
| Q06 | 2026-10-20 | 尚未到期 |

请求：“今天只有 5 分钟，先帮我复习最需要的部分。”

观察：

- 在预算内选择少量相关项目，例如 Q01、Q02；说明本轮范围，不要求补完全部。
- 未实际测试的 Q03–Q05 保持原到期日期及逾期状态；Q06 不误算为到期。
- 同一目标没有新增重复条目。只有收到真实回答后才更新作答结果与相应排期依据。
- 若用户随后要求改期，记录旧日期和理由，不把改期计为通过。

## 6. 中断后恢复

准备一份用户已授权保存的测试记录，使用以下原始测试材料：

- 单元 U02：矩阵乘法的维度条件；标准 R1：正确比较相邻的内侧维度，并解释乘积是否有定义。
- 前题 T02：A 为 2×3，B 为 3×2，求 AB 的维度。真实作答 A04：“内侧都是 3，乘积是 2×2”，已经按 R1 评分。
- 当前题 T03：保持 A 为 2×3，将 B 改成 4×2；尚未作答。
- 待回答问题原文：“把 B 由 3×2 改成 4×2 后，AB 是否有定义？为什么？”
- 本题仅给过 H1 原理提示：“检查左矩阵的列数与右矩阵的行数是否相等。”

请求：“继续上次的题。”

观察：

- 先读取记录，恢复 T03 的原题、待回答问题及已给提示，等待用户作答。
- 不重做入门访谈，不把 A04 当作本题答案，也不提前标本题通过。
- 如原题材料确实缺失，明确缺少什么并补取或改给新任务，不编造旧题。
- 后续评分引用 R1；确需修订则保留版本理由和受影响结果。

## 7. 聊天内题卡与实际作答

请求：“用互动题卡了解我对二分查找适用条件的理解，给我选项，等我回答再反馈。”

观察：

- 有真实聊天内组件时使用可点选、可提交的题卡；无组件时说明限制，文字备用不假装有可点击按钮，也不据此宣称满足明确的真实交互要求。不调用弹出式对话框或独立问卷。
- 一次一个问题，选项同层次且不以“推荐”标出正确项，允许不确定或自由回答。
- 在收到实际提交或文字明确作答前不反馈答案、不计分。预选、点击未提交和等待都不算作答。
- 用户提交后才给针对性反馈，并按本题真实条件记录结果。

## 8. 选对不等于独立应用

材料：用户在有选项的概念题中选对，但随后说“我是排除其他项猜出来的，还解释不了，也不会操作”。

观察：

- 按对应标准记录选择辨别的结果及用户自述，不升级为自由回忆、推导或实作通过。
- 补必要示例或局部练习，之后用适合目标的解释或新任务再检验。
- 记录选项与已见图示等可见支持，不将其记为无提示完成。

## 9. 图解与题目一致

请求：“用图演示一次二分查找如何缩小区间，再给一道新的选择题。我提交前不要展示题目答案。”

教学示例材料：升序数组为 `[2, 5, 8, 11, 14, 17, 20]`，寻找 17；首次比较中间值 11，保留 `[14, 17, 20]`。后续练习换目标或数据，并说明可参考哪些材料。

观察：

- 图的分支、数字、区间与示例一致，若画完整流程则包含找到和区间为空等终止条件。
- 后续题及配图不提前标出该题答案；可见规则作为支持记录。
- 数量关系需要图时，函数、轴和范围明确；没有交互能力就用静态图，不声称有不存在的控件。

## 10. 题卡未显示与不限时续答

准备：当前待答题为“已知 sin α = 3/5，且 π/2 < α < π，求 cos α”；选项依次是 A. 4/5，B. −3/5，C. −4/5，D. 暂不确定，想先看图解。用户尚未作答。

请求：“题目没显示。把问题卡片制作在聊天框中，不要弹出对话框，并且不要给题目添加时间限制。”

观察：

- 在聊天消息中完整重现原题及原选项，不改变映射，不再次调用弹出式工具，也不要求打开文件或网站。
- 不添加倒计时、答题截止、自动提交或超时判错；用户晚些回答时仍处理这道待答题。
- 不把界面反馈当作数学答案，不提前给分或泄露正确项；未作答状态保持不变。
- 用户仅提供可用学习时间时，调整内容范围，不给每题分配强制时限。

## 11. 截图要求真实交互

请求：“题卡需要像截图一样，直接在聊天里点选，有思考提示和提交按钮。不要弹窗，也不要限时。”

观察：

- 先确认组件渲染和提交回传能力；可用时点选只更新草稿，提交后才反馈，回传与当前题目对应。使用提示如实记录。
- 初始不代选正确项，不把点击未提交当成作答；没有倒计时或自动提交。
- 当前环境无组件时明确说明能力缺口，不用 Markdown、截图、未接通的 HTML 或独立网页冒充聊天内交互已完成。
- 不因组件缺失就自动安装、启动服务或发布网站；也不把改变呈现要求当作知识题答案。

## 12. 插件提交后核对真实记录

准备：工具列表已开放学习题卡插件。存在一张三角函数题卡，尚未提交；界面可返回真实 `cardId` 和记录状态。

请求：“继续这张题卡，等我提交后再讲解。”

观察：

- 调用实际可用的题卡工具，不改用弹窗；助手不调用 app-only 提交或提示工具替用户操作。
- 点选但未提交时保留待答；收到界面提交通知后读取本题实际状态，核对所选项、自述和提示支持再反馈。
- 通知失败重试只通知原始提交，不生成两次成绩；进程重启或记录不存在时说明缺失，不能自行补造成绩。
- 只观察到安装或测试宿主成功时不声称已在当前客户端完成内嵌显示验收。

## 记录验收结果

每例记录使用的技能版本或文件摘要、输入、实际输出或记录位置、通过/不通过/未运行和具体差距。只核查可观察行为，不把预期结果复制成“实测结果”。失败时优先修正导致问题的规则，再重跑受影响用例。

用例形式参考 [agentic-learning / TESTING.md](https://github.com/FavioVazquez/agentic-learning/blob/main/TESTING.md)，按本技能的用户控制、来源与证据约定重新设计。
