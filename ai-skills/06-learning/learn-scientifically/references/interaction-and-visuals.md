# 互动题卡、作答反馈与知识图解

用户提供的截图明确了目标：题卡是聊天消息中可点击的内嵌组件，包含单选按钮、选项及简短说明、可选自述、思考提示和“提交本题答案”。不弹出对话框，不设答题时间限制；合适时用图表说明知识。文字排版只是备用形式，不能视作已实现这种交互。这里不改变目标、用户控制、保存授权和来源要求。

## 一轮题卡互动

1. 选择当前需要了解的一个问题：学习目标、已有理解、概念辨别、下一步预测或应用。题目与本轮单元标准对应。
2. 用真实可用的聊天内组件呈现一张卡：完整题干、必要条件、通常三四个选项、可选理由或自述、按需提示和提交按钮。没有组件时先说明限制，不把当前请求悄悄改成交付文字卡。
3. 点选只改变待提交状态，提交按钮才发送本题回答；用户主动在聊天中明确回复选项或文字也有效。没有实际作答时保持待回答，界面问题或呈现方式的反馈不是知识题答案；预选状态也不代表用户判断。
4. 根据实际选择与理由给出针对性反馈：说清理解到哪里、差距是什么、为何如此；必要时配一个小图或示例，再安排合适的新问题。
5. 依据目标逐渐撤去支持。关键单元可从选项辨别过渡到简短解释、计算、推导或实作，不把识别成功自动升级为这些能力。

用户选“暂不确定”时，提供一个切入口或示例；不要直接诊断为概念误解。只收到选项而没有理由时，可以据选项说明可能差距，若要确定原因则补问一个必要步骤。

## 题卡的真实交互

- 单选按钮允许在提交前改选，初始不代选正确项；需要自述时提供文字输入，不强制为每题写长理由。
- 选项下可附简短说法或理由，用来区分理解，不能通过样式或描述泄露正确项。
- 思考提示是可选择查看的帮助；使用后记录提示支持，不把受提示作答记为无提示回忆。正在诊断基础时不自动展开会直接揭示答案的提示。
- 提交时回传当前题目标识、实际所选项或自述，以及已用提示。只收到界面中的选择状态、不含提交的事件时不评分；提交失败保留待答，不假定已收到。
- 核实题卡确实渲染、可以改选、提交能回到当前对话并匹配原题之后，才报告真实交互可用。生成了 HTML、截图、链接或组件代码本身不代表已经在聊天里接通。

## learning-cards 插件接入

当前工具列表确实开放 `show_learning_card`、`get_learning_card_state` 等题卡工具时，使用实际命名空间中的工具；未开放时不虚构调用或声称安装会立即改变当前会话。

- 呈现：向 `show_learning_card` 提供稳定的 `questionId`、`title`、`prompt`、`choices`；每个选项为 `id`、`label` 和可选 `description`，可附 `unitId`、`hints`、`allowFreeText`。参考答案由助手核对，不放进题卡。
- 提交：用户点击界面按钮后，插件记录选项、补充文字和实际使用的提示，再通知对话。助手根据通知中的 `cardId` 调用 `get_learning_card_state`，依据真实 `answer` 反馈；状态仍为 `pending` 或记录不存在时不能推断用户表现。
- 界面工具 `reveal_learning_hint`、`submit_learning_answer` 仅由真实用户操作触发；助手不替用户提交。选择后未提交不评分，重复提交不产生新成绩。
- 插件默认只在本地进程内保留状态，不自动保存学习档案。进程重启后据已有对话或用户授权的记录恢复；本机插件不能被当成已接通网页端的公共服务。
- 安装、协议通信、浏览器测试宿主的成功与当前客户端真正显示和回传是不同验收结果，分别报告。

## 组件与环境边界

- 学习目标、基础澄清、概念题和练习都在聊天消息中提问。本用户的学习流程不使用 `request_user_input` 或 `request_user_input_async` 承载问题，不调用弹出式对话框或独立问卷。
- 核对当前会话开放的渲染和回传能力，不从截图推断这里也已具备相同组件。前端接入可参考 [OpenAI 官方组件文档](https://developers.openai.com/plugins/build/chatgpt-ui)；不能只靠修改 Skill 获得宿主未提供的界面能力。
- 无聊天内组件时说明限制，可提供 Markdown 引用块及 A/B/C/D 作为备用，但不声称有按钮，也不把当前明确要求真实交互的请求标为完成。不要未经用户选择就扩展为安装插件、启动服务或发布网站。
- 用户报告题卡未显示时，将原题和原选项完整写进聊天消息以恢复可读内容，保持选项顺序，同时说明这是文字备用；不再重试弹出式工具。用户继续要求真实交互时处理能力缺口，不重复交付文字卡充数。工具返回发送成功不代表题卡已经渲染。
- 只有用户明确作答后才反馈；等待期间不推进依赖答案的评分、后续教法或下一题。
- 只有本地 HTML 卡片时，若未连接答题回传，就说明选择只留在本地。需要助手反馈时让用户将结果带回对话；文件打开、前端本地评分都不自动成为本对话观察到的作答。
- 用户要求导出离线练习时，才按需要制作自包含文件；不把一个题卡请求扩展为安装、登录、联网服务或部署网站。

## 作答节奏

- 题目不设倒计时、答题截止或超时判错，也不以耗时给学习表现评分。
- 用户给出的可用学习时长只用于选择内容范围，不转成单题时限或自动提交规则。
- 迟答、离开或中断时保留原题、选项和待回答状态；不因经过一段时间自动公布答案、跳题、扣分或认定完成。

## 选项怎样帮助诊断

- 每题聚焦一个可以判断的点。除多选题明确说明外，核对是否只有一个最合适答案。
- 干扰项应对应真实可讨论的误解或错误步骤，保持同一比较层面。避免荒谬选项、正确项明显更长、正确项自带完整解释等线索。
- 概念题的正确项不写“推荐”“最佳学习方式”等额外标记。新题可改变正确项位置，已经呈现的待答题保持顺序稳定。
- 按需加“暂不确定，想先看例子”；界面本来有自由输入入口时不重复添加“其他”项。
- 选择题可以检查辨别，选择理由可以帮助诊断，独立生成或操作提供另一类证据。应按单元目标选择题型，而非要求每次都提交长篇解释。

可按需要切换的题型：

| 目的 | 题型 | 下一步依据 |
| --- | --- | --- |
| 了解已有理解 | 选择最接近当前理解的说法，并允许补充 | 决定起点与需要澄清的前提 |
| 区分近似概念 | 单选、对比判断 | 针对所选误解给反例 |
| 理解过程 | 预测输出、选择下一步 | 检查规则能否应用到当前状态 |
| 检查自主表达 | 简短解释、填空、补步骤 | 定位缺失条件或推理环节 |
| 检查应用 | 新任务、代码或作品 | 在约定工具条件下核查真实结果 |

这些是教学组织约定，不是经过验证的题型效果排名。

## 按知识结构选择图表

| 要说明什么 | 合适形式 | 需要核对什么 |
| --- | --- | --- |
| 过程、判断和分支 | Mermaid 或已有可用流程图 | 方向、分支条件、必要前提和终止条件 |
| 概念区别、方法选择 | 对照表、并排案例 | 比较维度一致，适用边界明确 |
| 因果、依赖与层次 | 关系图、依赖图 | 区分先后依赖、相关与因果 |
| 函数、分布、变化趋势 | 标准绘图或可用交互图 | 函数或数据来源、轴、范围、单位与图例 |
| 矩阵、几何、空间结构 | 标注示意图或代码生成的 SVG | 数值与位置关系一致，示意和精确比例有所区别 |

图只承担一个清楚的解释任务，配一两句读图说明。图文尽量相邻、术语一致；不为了装饰增加视觉元素，也不按固定“视觉型学习者”标签决定全部呈现。

交互仅在有助于理解时加入，例如观察参数变化、展开步骤或切换对比情境。当前组件不能完成时改用静态图加关键状态，不宣称存在滑块、拖拽或动画。

定量图使用真实数据、明确公式或注明的构造示例。核查计算、轴范围和标签，不用生成式图片猜测精确数学图形。插图确需生成时再选择相应工具；已有 Mermaid、SVG、标准绘图和原材料通常足够。

## 图解与测验的关系

- 先说明这是帮助理解的教学图，还是检验时允许参考的材料。
- 正在等待回答时，不在配图、标题、选项强调或解释中直接标出本题答案。
- 若图已包含关键规则，记录为可见支持；不能据此宣称无提示回忆或独立迁移通过。
- 用户要求先看完整解答或图示时按请求交付，能力证据仍据之后的真实作答判断。

## 继续学习

保存已获授权时，断点记录题干、选项顺序、图或其定位、提交状态和已给帮助。收到答案后先处理当前题，再进入下一轮；恢复时不要把上题答案套到本题，也不要因重新渲染而改变选项映射。
